# Reproducing the paper (mutation side)

This document covers the floats regenerated by the SkillMutator pipeline: **Table 3** (safety-refusal summary), **Table 4** (cross-scanner detection-rate matrix), **Table 5** (select vs no-select) and **Figure 4** (IER dynamics). The fine-tuned-scanner floats are covered by `../finetuning-framework/docs/REPRODUCE.md`. Every claimed number is also verified from bundled data at Tier 1 (`./run.sh --tier 1` at the artifact root); this document is for regenerating the mutation-side floats live.

## What you need

| Resource | Purpose | Approx. cost / time |
|----------|---------|---------------------|
| OpenAI API access (GPT-4o-mini, GPT-5.4-mini, GPT-5.4) | Three adversarial oracles, LLM scanners, GPT-5.4 evaluation judge | ~$30+ API (expected ~$200 for the full paper setting); ~3 h+ |
| Snyk account (optional) | Snyk Agent Scan baseline (`SNYK_TOKEN`); without it the Snyk cells show n/a | Free tier sufficient |
| 68 + 17 community/Anthropic skills | 68 community skills are mutated to build the fine-tuning training corpus; the 17 Anthropic skills are mutated for the benchmark (cloned automatically) | See [SKILLS_SETUP.md](SKILLS_SETUP.md) |
| ~60 GB disk | Mutated tree, scan reports and verdicts (~1.4 GB), plus base models, LoRA adapters (~2.5 GB) and run outputs for the fine-tuning side, with headroom | — |
| 1 GPU (optional) | Required only for the fine-tuning side | — |

## End-to-end reproduction

### 0. Environment

```bash
# from the artifact root
./install.sh --generate        # .venv + openai, langchain-core/-openai, langgraph, tiktoken,
                               # python-dotenv, matplotlib + skill-security-scan + Snyk Agent Scan
cp .env.example .env           # fill in OPENAI_API_KEY (SNYK_TOKEN optional)
# run.sh sets SKILLMUTATOR_DATA_ROOT (default ./demo-data); do not point it at a
# folder that already holds other data, run.sh refuses to clean such a folder.
```

### 1. Run the full benchmark

`./run.sh --tier 4 --no-gpu --env-file .env` at the artifact root runs the whole mutation side. The same loop by hand, from this folder (`artifact/code/skillmutator`):

```bash
rm -rf demo-data
for m in gpt-4o-mini gpt-5.4-mini gpt-5.4; do
  ./run.sh --model "$m" --judge-model gpt-5.4 --iters 5 --cross-scan --keep-data \
           --crawl 17 --registry anthropic --skills-dir ./skills/anthropic --env-file <.env>
done
./run.sh --model gpt-5.4 --judge-model gpt-5.4 --iters 3 --mode no-select --cross-scan --keep-data \
         --crawl 17 --registry anthropic --skills-dir ./skills/anthropic --env-file <.env>   # Table 5
```

`--crawl 17 --registry anthropic` clones the 17 Anthropic evaluation skills into `./skills/anthropic`.

### 2. What each run.sh pass does

1. `scripts/run_mutation.py` mutates each skill (`--mode`, `--max-iters`, `--use-llm-detect`) and scans every iteration with skill-security-scan, Snyk Agent Scan and the oracle's own LLM scanner.
2. `scripts/consolidate_to_datatree.py` writes the canonical data tree (`$SKILLMUTATOR_DATA_ROOT/<oracle>/<mode>/<skill>/<category>/iter_<k>/`) with the mutated package, an `injected_content.md` ground-truth note and a `meta.json` that labels each iteration normal / explicit_refusal / silent_failure / partial_refusal.
3. `scripts/populate_verdicts.py` writes the skill-security-scan and Snyk `verdict.json` cells.
4. `scripts/judge_llm_scanners.py` scans each scenario's last normal iteration with the other two LLM scanners (`--cross-scan`) and adjudicates every LLM report with the evaluation judge (`analysis/skillmutator_utils/judge.py`, the Figure 7 prompt).
5. `analysis/paper_floats/{table3_refusal,table4_cross_scanner,table5_select,figure4_ier}.py` build the floats into `analysis/paper_floats/outputs/<float>/`.

## Validation

| Cell                                  | Expected detection rate |
|---------------------------------------|-------------------------|

## Caveats

- Table 4 evaluates 48 / 63 / 76 scenarios per oracle (GPT-4o-mini: 51 attempted, 3 without a valid mutated package; see the claim02 README), as described in §6.1 Experimental Setup of the paper.
- Live tables show n/a for a cell with no verdict (scanner unavailable, or not run in this run).
- The SkillScan API rows of Tables 4/5 and the prompt-injection-detector rows of Table 4 are verified at Tier 1 only; the live pipeline does not run those scanners.
- The 4-Phase distilled scanner result (paper Figure 6, §6.4 Fine-tuning Effectiveness, Finding 4) is reproduced on the fine-tuning side, not here.
