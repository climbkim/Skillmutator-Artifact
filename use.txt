SkillMutator artifact — commands & options
===========================================

WHAT reproduces WHAT (claim -> table/figure), expected values, and requirements
are in README.txt / README.md. This file is the command + option reference.

Adversarial (mutated) skills are NOT bundled, to prevent misuse; they are
generated on disk only when the live pipeline (Tier 2-4) is run. Use them only
as scanner inputs in an isolated environment; do not install or execute them
against a live agent (see ETHICS.md).
No personal data is included. API keys are read from a local .env and are never
bundled.


0. Install
----------
  ./install.sh                 # Tier 1 core deps (CPU): pandas numpy pyyaml openpyxl
  ./install.sh --generate      # + mutation/scan extras (openai, langchain*, langgraph,
                               #   tiktoken, python-dotenv, matplotlib)
                               #   + snyk-agent-scan + skill-security-scan (third-party scanners)
  ./install.sh --finetune      # + GPU training/inference (torch, transformers, peft, vllm, ...)
  ./install.sh --all           # generate + finetune
  PYTHON=<interp> ./install.sh  # choose the base Python (default python3)
  # --finetune / --all need Python 3.10-3.12 (vllm 0.8.5, sentencepiece 0.2.0 have
  # no 3.13+ builds), e.g.  PYTHON=python3.12 ./install.sh --all


Quick start (one command per tier)
----------------------------------
  # Tier 1  verify the 12 table/figure claims    CPU · no key · free · ~minutes   << START HERE
  ./install.sh && ./run.sh --tier 1

  # Tier 2  live demo on the sample skill     needs OPENAI_API_KEY (in .env)
  ./install.sh --generate && ./run.sh --tier 2 --no-gpu --env-file .env     # no GPU
  ./install.sh --all      && ./run.sh --tier 2 --env-file .env              # with a GPU (adds FT scan)

  # Tier 3  paper skills, default settings     key + (GPU unless --no-gpu) + network
  ./install.sh --all && ./run.sh --tier 3 --env-file .env                   # add --no-gpu to skip FT

  # Tier 4  full benchmark + training demo     key + A100 80GB + network
  ./install.sh --all && ./run.sh --tier 4 --env-file .env

  Put OPENAI_API_KEY in a .env beside run.sh (or pass --env-file PATH). Add
  --no-gpu to any tier to skip the GPU finetune step. Add --dry-run to preview
  the plan + HW/SW/cost without running.


1. One-command tiers (top-level dispatcher)
-------------------------------------------
  ./run.sh --tier N [--no-gpu] [--env-file PATH] [--dry-run]

    --tier 1   data verification    CPU, no key/GPU        ~minutes        $0
    --tier 2   sample skill, no train  API key (+GPU for finetune side)    few min
    --tier 3   paper skills, no train  API key + GPU ~16GB + network       hours
    --tier 4   full benchmark + train demo  A100 80GB + API key + network  ~3 h+ + ~1-2 h

  --no-gpu     run ONLY the parts that need no GPU (CPU claims + the skillmutator
               CPU+API pipeline); skip the GPU finetune steps. The skillmutator
               side never needs a GPU; the finetune side does. (No effect at Tier 1.)
  --env-file   load OPENAI_API_KEY (and SNYK_TOKEN/LLM_*) from this .env
  --dry-run    print the plan + per-tier HW/SW/time/cost, run nothing

  Cost (est., grounded in claim06 + REPRODUCE.md; gpt-4o-mini default vs GPT-5.4 paper):
    Tier 2  : a few US cents  /  < $1        (+ ~$0.5 GPU on the finetune side)
    Tier 3  : ~$2-3 API (gpt-4o-mini default) + ~$0.5 GPU; one oracle at the paper
              settings (section 4) is ~$15-25+ API with gpt-5.4 (est., not measured)
    Tier 4  : estimates (GPU at $1.10/h):
              1 skillmut  CPU+API  ~3 h+   ~$30+ API, expected ~$200 (17 skills x3 oracles, iter_0-4,
                                           gpt-5.4 judge, cross scans, + no-select pass;
                                           this setting is not measured and costs more)
              2 FT demo   A100+API ~1-2 h  ~$1-2 GPU + < $1 API (base Qwen 7B download,
                                           teacher distill of <= 24 skills, 5-step LoRA
                                           run, released-adapter scan of 2 skills)
  A100 rate = paper's $1.10/h (claim06). The training demo shows the process; it
  does not rebuild the paper's adapters. Paper-scale training is NOT automated:
  full corpus distillation (1219 examples, ~4,900 calls, RECORDED ~$40-60 with the
  GPT-5.4 teacher), 4 base families from scratch (MEASURED ~25 A100-h; a single
  Qwen scanner is 4.5 h, train_runtime 16,275 s), vLLM batch scan (~3-4 A100-h);
  every Table 6 phase + a/epoch ablation is the full ~72 A100-h (~3-day, ~$80)
  campaign. These results are verified at Tier 1 (claims 04, 10, 11, 12; cost in
  claim06). Live output is nondeterministic.


2. Tier 1 — data verification (CPU, no key, no GPU)
---------------------------------------------------
  ./run.sh --tier 1                        # all 12 table/figure claims (CPU)
  # or a single claim directly:
  cd claims/claim04_phase_ablation && ./run.sh    # rebuild + verify (PASS/FAIL)
Each claims/claimNN/run.sh regenerates its aggregate from bundled verdicts and
checks it against the paper-cited values and tolerances in
expected/metrics.json (human-readable copy: expected/PAPER_CITED_VALUES.md).
(Claim list + expected values: README.)


3. Tier 2 — sample skill, no training
-------------------------------------
Mutation side (regenerates Tables 3/4/5 + Figure 4 at demo scale):
  cd artifact/code/skillmutator
  ./run.sh                                 # default: sample skill, gpt-4o-mini
  Options:
    --model MODEL          oracle + LLM-scanner model         (default gpt-4o-mini)
    --judge-model MODEL    evaluation judge for the LLM-scanner rows (Figure 7
                           prompt; paper uses gpt-5.4; default gpt-4o-mini).
                           run.sh first checks that the key can use this model.
                           A failed judge call leaves no verdict and stops the
                           run before the tables are built.
    --iters N              N iterations iter_0..iter_{N-1}    (default 2; paper: 5 select, 3 no-select)
    --mode MODE            select | no-select                 (default select)
    --cross-scan           also scan each scenario's final iteration with the
                           other two LLM scanners (Table 4 cross cells)
    --keep-data            keep other oracles/modes in the data tree (Tier 4 loop)
    --skill PATH           mutate a specific skill folder      (has SKILL.md)
    --crawl N              fetch N skills first, then mutate the pool
    --registry NAME        crawl source: anthropic | clawhub   (default clawhub)
    --skills-dir DIR       where crawled skills land            (default ./skills/<registry>)
    --env-file PATH        load OPENAI_API_KEY (+ SNYK_TOKEN/LLM_*) from a .env
  Outputs -> analysis/paper_floats/outputs/<float>/

Fine-tuning side (released adapter, no training):
  cd artifact/code/finetuning-framework
  SKIP_TRAIN=1 ./run.sh                    # fetch adapter + scan the mutation made above
                                           #   and the benign sample + tables


4. Tier 3 — paper skills, default settings (released adapter, no training)
--------------------------------------------------------------------------
Mutation side (17 Anthropic eval skills, auto-cloned; one oracle at the default
settings: gpt-4o-mini oracle and judge, 2 iterations, no cross LLM scans):
  cd artifact/code/skillmutator
  ./run.sh --crawl 17 --registry anthropic --skills-dir ./skills/anthropic --env-file <.env>
  # community/wild corpus instead: --registry clawhub  (reads
  #   artifact/data/clawhub/clawhub_skills.csv; only SKILL.md is re-fetchable)
  # paper settings for one oracle (as in Tier 4; e.g. the n=76 gpt-5.4 set):
  ./run.sh --model gpt-5.4 --judge-model gpt-5.4 --iters 5 --cross-scan \
           --crawl 17 --registry anthropic --skills-dir ./skills/anthropic --env-file <.env>
  #   Table 5 also needs the no-select pass, and the other oracles' columns
  #   need their own runs (see Tier 4).
Fine-tuning side (released adapter, one mutated + one benign skill, as in Tier 2):
  cd artifact/code/finetuning-framework
  SKIP_TRAIN=1 ./run.sh


5. Tier 4 — full benchmark + fine-tuning training demo
-------------------------------------------------------
Mutation side (all three oracles, judge gpt-5.4; one accumulated data tree):
  cd artifact/code/skillmutator
  rm -rf demo-data
  for m in gpt-4o-mini gpt-5.4-mini gpt-5.4; do
    ./run.sh --model "$m" --judge-model gpt-5.4 --iters 5 --cross-scan --keep-data \
             --crawl 17 --registry anthropic --skills-dir ./skills/anthropic --env-file <.env>
  done
  ./run.sh --model gpt-5.4 --judge-model gpt-5.4 --iters 3 --mode no-select --cross-scan --keep-data \
           --crawl 17 --registry anthropic --skills-dir ./skills/anthropic --env-file <.env>   # Table 5
Fine-tuning side (training demo, then a released-adapter scan):
  cd artifact/code/finetuning-framework
  ./run.sh                                 # [A] distill <= 24 skills, [B] 5-step LoRA run,
                                           # [C]-[F] released-adapter scan + judge + tables
  Paper-scale training is not automated (see Tier 4 notes above and
  docs/REPRODUCE.md); only the Qwen training config is shipped.
  Env knobs (defaults): SKIP_TRAIN=0|1  SKIP_SCAN=0|1  MAX_STEPS=5  DATAGEN_MAX=24
    TEACHER=gpt-4o-mini (demo; the released adapter was distilled with GPT-5.4)
    JUDGE_MODEL=gpt-4o-mini  BASE_MODEL=Qwen/Qwen2.5-Coder-7B-Instruct
    ADAPTER_REPO=climbkim/skillmutator-scanner-adapters  OUTPUT_DIR=./output_demo
    DATASET_DIR=$OUTPUT_DIR/dataset


6. Environment variables
------------------------
  OPENAI_API_KEY   REQUIRED for Tiers 2-4 (oracle + LLM scanner + judge/teacher).
  SNYK_TOKEN       OPTIONAL — enables the Snyk scanner; without a valid token the
                   Snyk cells are shown as n/a and the run still proceeds. A
                   .env.example placeholder counts as no token.
                   (In the live tables, n/a means no verdict for that cell: not run
                   in this run, e.g. no --cross-scan or no no-select pass, or the
                   scanner was unavailable.)
  HF_TOKEN         HuggingFace access for base models / adapters (finetune side).
  LLM_PROVIDER / LLM_MODEL     optional LLM-scanner defaults.
  SKILLMUTATOR_DATA_ROOT       canonical data tree root (default ./demo-data). run.sh cleans it
                               only if it is ./demo-data or a folder run.sh created; it refuses
                               to clean any other non-empty folder. The top-level ./run.sh
                               --tier 2-4 always uses artifact/code/skillmutator/demo-data.
  SKILLMUTATOR_ORACLE          oracle key for Table 5 (set by run.sh to --model).
  SKILLMUTATOR_CLAWHUB_CSV     override the ClawHub manifest path (--registry clawhub).
  SKILLMUTATOR_CLAWHUB_POOL    optional pool filter, e.g. clean_175.
Copy the top-level .env.example to .env (beside run.sh) and fill in what you
need. `./run.sh` auto-loads that .env (or pass --env-file PATH) and exports the
keys to every sub-script; placeholder/unset values are ignored. Tier 1 needs
none of these. The per-framework run.sh scripts additionally auto-load a .env
from their own folder or a parent.


7. What needs external resources
--------------------------------
  - Tier 1 (claims/): nothing — pure Python over bundled CSVs.
  - Mutation generation / LLM-mode scanning (Tiers 2-4): OpenAI API access.
  - Fine-tuned 7B scanner / training (Tiers 2-4): a GPU (A100 80GB for training);
    LoRA adapters on Hugging Face (see the Availability table in README).
  - Third-party scanners (pip, via ./install.sh --generate): skill-security-scan
    (MIT) and snyk-agent-scan (Apache-2.0; also needs a SNYK_TOKEN). Both are
    optional — absent, that scanner is skipped and the run still proceeds.
  - Skill bodies are not redistributed: the 17 Anthropic eval skills are cloned
    from their public repo; the ClawHub corpus ships as a URL manifest
    (artifact/data/clawhub/clawhub_skills.csv); the full 1219-example training
    corpus is available from the authors on request.
